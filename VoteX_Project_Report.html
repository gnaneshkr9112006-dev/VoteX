Abstract

Democratic and institutional elections remain vulnerable to centralized server manipulation, ballot tampering, voter impersonation, and coercion. Conventional Electronic Voting Machines (EVMs) lack universal cryptographic verifiability, while early web-based voting portals suffer from centralized database vulnerabilities where a single database administrator can alter vote tallies unnoticed.

This project presents VoteX, a production-ready, mobile-first, decentralized election platform that unites multi-factor carrier verification, dual-layer biometrics, and Ethereum smart contracts. Voter identity is certified through real-time cellular SMS one-time passcodes dispatched via the Twilio Verify API, paired with dual biometric authentication comprising real-time 128-dimensional facial embedding Euclidean distance comparison (≤ 0.54 calibrated threshold) and hardware WebAuthn fingerprint sensors.

To resolve the fundamental contradiction between double-voting prevention and voter anonymity, VoteX generates salted SHA-256 cryptographic voter commitments. The smart contract (ElectionRegistry.sol) records commitments on an immutable distributed ledger while tallying votes into candidate buckets without preserving any traceable link between the voter's identity and their choice. Furthermore, the architecture introduces multi-tenant room partitioning capable of executing 50+ concurrent elections simultaneously with isolated access controls and cryptographic receipts.

Key Contributions: (1) Carrier-grade Twilio Verify SMS integration with zero on-screen credential leakage. (2) Server-side Euclidean mathematical verification of 128D facial vectors with liveness detection. (3) Solidity smart contract ensuring zero double-voting and immutable consensus-based tallying. (4) High-density multi-tenancy supporting 50+ independent simultaneous elections. (5) Public cryptographic receipt verification providing mathematical proof of ballot inclusion.

Chapter 1: Introduction & Problem Statement

1.1 Background & Motivation

Voting is the bedrock of democratic governance, collegiate elections, and corporate decision-making. Despite technological modernization in banking, healthcare, and communications, election mechanisms remain largely antiquated or susceptible to systemic flaws:

  • Paper Ballots: Physical paper voting requires massive logistical expenditures, physical booth guarding, and hours of manual counting, while remaining susceptible to ballot stuffing, physical theft, and invalid markings.
  • Standalone EVMs: Electronic Voting Machines, while efficient in counting, operate as opaque black boxes lacking open mathematical transparency. Voters must blindly trust the machine firmware without receiving verifiable cryptographic receipts.
  • Centralized Web Voting Portals: Early digital voting portals store votes in conventional relational databases (MySQL, PostgreSQL, MongoDB). In these systems, a single SQL query (UPDATE votes SET candidate_id = 'X') can overturn an entire election without generating a cryptographic audit trail.

1.2 Problem Statement

How can an election system be designed to satisfy three mutually conflicting axioms simultaneously:

  1. Eligibility & Uniqueness: Strictly verify the identity of the voter and guarantee that no person can cast more than one ballot.
  2. Unconditional Privacy (Secret Ballot): Prevent the server, election officers, observers, or blockchain miners from discovering who voted for whom.
  3. Immutable Public Verifiability: Provide mathematical certainty to both the voter and the public that all cast ballots were accurately recorded and cannot be altered retrospectively.

1.3 Objectives of VoteX

  • Implement a 3-factor voter authentication pipeline combining Room Access Credentials, Cellular SMS Verification via Twilio Verify, and Biometric Identity Certification.
  • Engineer a dual-biometric engine supporting both 128-dimensional facial recognition with calibrated Euclidean distance matching and WebAuthn hardware passkeys/fingerprints.
  • Develop and deploy an Ethereum smart contract (ElectionRegistry.sol) that records votes using cryptographic commitments to eliminate double-voting while safeguarding secrecy.
  • Create a multi-tenant Election Room subsystem allowing institutions to run 50+ simultaneous elections in parallel with isolated candidate rosters and voter populations.
  • Deliver real-time turnout analytics via WebSocket event streaming paired with public receipt verification tools.

Chapter 3: Core Functional Modules

3.1 Module 1: Two-Factor Cellular SMS Verification

Voter authentication begins with phone number verification. To prevent unauthorized account access and eliminate simulated test codes in production, VoteX integrates the Twilio Verify v2 API:

  • Carrier Dispatch: When the voter requests an OTP, VoteX issues an authenticated POST /v2/Services/{SERVICE_SID}/Verifications request to Twilio. Twilio generates a cryptographically secure 6-digit passcode and transmits it across the cellular carrier network to the voter's physical handset.
  • Zero Website Leakage: The server never returns the OTP in the HTTP response JSON. The client displays no on-screen code or auto-fill buttons.
  • Carrier-Grade Validation: When the voter submits their 6-digit code, the server submits it to /VerificationCheck. Only if Twilio responds with valid: true does the voter gain authorization to proceed to the biometric checkpoint.

3.2 Module 2: Dual Biometric Verification Engine

VoteX offers two distinct biometric authentication pathways to ensure maximum accessibility across diverse device hardware:

Pathway A: 128-Dimensional Neural Facial Euclidean Distance

When face recognition is selected, the client streams the user's camera feed through an SSD MobileNet neural network. It extracts a 128-element floating-point descriptor representing invariant facial features (nodal points, eye socket depth, jawline contour).

The server compares the live vector L against the registered reference vector R enrolled during voter registration by calculating the Euclidean distance metric:

d(L, R) = √( Σi=1..128 (Li - Ri)² )

Through extensive empirical calibration, VoteX enforces a strict threshold of d ≤ 0.54. Distances below 0.54 certify positive human identification, while higher distances trigger immediate rejection and security audit logging.

Pathway B: Hardware WebAuthn Fingerprint Passkeys

For devices equipped with fingerprint scanners or touch ID sensors, VoteX invokes the W3C WebAuthn browser API. The voter provides their fingerprint to their hardware secure enclave, generating a cryptographically signed authentication assertion verified by the server.

Chapter 4: Blockchain Smart Contract & Voter Privacy

4.1 Cryptographic Voter Commitments

To guarantee voter anonymity while preventing double-voting, VoteX decouples the voter's identity using a one-way salted hash:

voterCommitment = SHA-256( Voter_ID + Server_Salt )

This produces a 32-byte hash (e.g. 0x7f83b165...). The blockchain contract maintains a mapping: 

mapping(bytes32 => bool) hasVotedMapping;

When a vote is cast, the contract checks: 

require(!election.hasVotedMapping[voterCommitment], "Voter has already voted");
election.hasVotedMapping[voterCommitment] = true;

Because the candidate selection (voteCounts[candidateId] += 1) is updated independently, no observer, miner, or administrator can ever connect the commitment hash to the chosen candidate.

4.2 Running 50+ Concurrent Elections (Multi-Tenancy)

VoteX is engineered to manage high-volume institutional elections where dozens of departmental or club elections take place simultaneously.

Isolation Dimension Implementation in VoteX
On-Chain Storage Partitioning Each election is indexed by bytes32 electionId in mapping(bytes32 => Election) private elections. Storage slots for Room #1 and Room #50 are completely isolated.
Independent Voter Roster Voter participation is tracked per room in the junction table room_voters (election_id, voter_id, has_voted). A student voting in Election #1 retains an eligible has_voted = 0 status in Election #2 through Election #50.
Delegated Administration Super administrators can assign specific Election Rooms to departmental officers. Department admins cannot view, edit, or tamper with votes in other rooms.
Independent Time Windows Each room specifies its own start_time and end_time. Rooms automatically open and close according to their programmed schedule.

Chapter 5: Verification, Security & Results

5.1 End-to-End Cryptographic Receipt Verification

Upon casting a ballot, the voter receives an on-chain receipt code (e.g. VTX-A8F291CB), a transaction hash, and a block number: 

function verifyReceipt(bytes32 electionId, string memory receiptId) 
    external view returns (bool exists, bytes32 proofHash, uint256 timestamp);

Any voter can paste their receipt code into the public verification portal to inspect the cryptographic proof hash and block timestamp directly on the blockchain ledger, confirming their ballot was included in the certified tally.

5.2 Comprehensive Security Threat Model

Threat / Attack Vector Potential Vulnerability VoteX Defense Mechanism
Database Tally Tampering Admin changes SQL vote table. Blocked. Final tallies are computed by the Ethereum smart contract; database only caches results.
Voter Impersonation Stolen voter ID credentials. Blocked. Requires 2FA cellular phone access (Twilio SMS) AND live facial or fingerprint biometrics.
Double Voting Voter attempts voting multiple times. Blocked. Enforced at 3 levels: Database constraint, API controller lock, and Smart Contract revert.
Biometric Presentation Attack Attacker holds up a printed photo. Blocked. Anti-spoof liveness verification checks for dynamic micro-expressions and real human eye blinking.
Ballot Secrecy Violation Correlating voter identity with vote. Prevented. One-way salted commitments decouple human identity from candidate choices.

5.3 Conclusion & Future Enhancements

The VoteX project demonstrates that digital voting can achieve institutional-grade security, mathematical transparency, and complete privacy without sacrificing user convenience. By combining carrier-verified cellular SMS, calibrated neural biometrics, and Ethereum smart contracts, VoteX bridges the gap between paper ballot trust and digital speed.

Future Scope: Upcoming iterations will integrate Zero-Knowledge SNARKs (zk-SNARKs) for complete client-side zero-knowledge proof generation, off-chain Layer-2 rollups (such as Arbitrum or Polygon zkEVM) for sub-cent gas fees during mega-elections, and decentralized IPFS photo storage for voter registries.
